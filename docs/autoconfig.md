# Autoconfig

Autoconfig gathers the low-level configuration of the application from the `composer.json` files of
the root package and of every installed package. It is generated by the `icanboogie/autoconfig`
Composer plugin whenever packages are installed or updated, and written to
`vendor/icanboogie/autoconfig.php`.

The result is an `ICanBoogie\Autoconfig\Autoconfig` instance, available as `$app->autoconfig`:

| Property          | Description                                                                     |
|-------------------|---------------------------------------------------------------------------------|
| `base_path`       | The root of the project.                                                        |
| `app_path`        | The main application directory (`app/` by default).                             |
| `app_paths`       | Directories scanned for the application.                                        |
| `config_paths`    | Config directories, with their weight (`path => weight`).                       |
| `config_builders` | Config classes with the builder class that creates them (`Config => Builder`).  |
| `locale_paths`    | Locale directories.                                                             |
| `filters`         | Callables that may amend the autoconfig.                                        |
| `boot_callables`  | Callables `boot()` invokes with the application, in dependency order.           |

## Participating

A package participates through the `extra.icanboogie` section of its `composer.json`. This package,
for example, declares:

```json
{
  "extra": {
    "icanboogie": {
      "config-path": "config/",
      "config-constructor": {
        "ICanBoogie\\AppConfig": "ICanBoogie\\AppConfigBuilder"
      }
    }
  }
}
```

Supported options:

- `config-path`: a directory containing [config fragments](configuration.md) and `services.yml`.
- `config-weight`: where the path sits in the merge order. Constants on `Autoconfig`:
  `CONFIG_WEIGHT_FRAMEWORK` (-100), `CONFIG_WEIGHT_MODULE` (0), `CONFIG_WEIGHT_APP` (100). Heavier paths are
  processed later and can override lighter ones.
- `config-constructor`: maps a config class to the builder that creates it.
- `locale-path`: a directory of locale messages.
- `app-path`, `app-paths`: application directories.
- `autoboot`: one or more `Vendor\Class::method` callables invoked while the application boots, see
  [Booting packages](#booting-packages).
- `autoconfig-extension`, `autoconfig-filters`: extend or amend the generated autoconfig.

The authoritative list is the plugin's `schema.json`.

## Booting packages

A package that must wire itself in when the application boots registers a static callable with
`autoboot`:

```json
{
  "extra": {
    "icanboogie": {
      "autoboot": "ICanBoogie\\Binding\\Prototype\\Boot::boot"
    }
  }
}
```

```php
<?php

use ICanBoogie\Application;

final class Boot
{
    public static function boot(Application $app): void
    {
        // …
    }
}
```

`boot()` invokes the callables with the application, after the application is constructed and
before `BootEvent` is emitted. Packages boot in dependency order, and a package's callables keep
their declared order. Exceptions are not caught.

Autoboot is for packages wiring themselves in; `BootEvent` is for reacting to a booted application.
Code that never calls `boot()` (a Composer script, a standalone CLI script) doesn't run boot
callables.

To change what a package registered, use an `autoconfig-filters` callable that returns
`$autoconfig->with([ 'boot_callables' => … ])`.

## Obtaining the autoconfig

```php
<?php

use ICanBoogie\Autoconfig\Autoconfig;

$autoconfig = Autoconfig::get();
```

`Autoconfig::get()` resolves and memoizes the generated file. `boot()` calls it for you unless you
pass your own.

## Altering the autoconfig

`Autoconfig` is immutable. `with()` returns a modified copy, which is handy in tests:

```php
<?php

use function ICanBoogie\boot;

$autoconfig = Autoconfig::get()->with([
    'app_path' => __DIR__ . '/app/default/',
]);

boot($autoconfig);
```

## Listing what was collected

`php vendor/bin/icanboogie configs` (see [Console](console.md)) lists the config fragments and the
builders registered through autoconfig.
